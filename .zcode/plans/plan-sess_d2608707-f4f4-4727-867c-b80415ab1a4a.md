## PARTIE 1 — MODÈLE « CONGÉ » (backend)

### 1.1 `apps/api/prisma/schema.prisma`
- Ajouter `LEAVE` à l'enum `AttendanceSummaryStatus`.
- Ajouter `LEAVE_DECLARED` à l'enum `NotificationType`.
- Ajouter le modèle `LeaveDeclaration` (structure d'`OvertimeDeclaration` mais en plage de dates, sans champs de taux) :
  - `id, employeeId, dateStart, dateEnd, note?, declaredById?, status ApprovalStatus @default(PENDING_APPROVAL), approvedById?, approvedAt?, createdAt, updatedAt`
  - relations : `employee` (Cascade), `declaredBy User? @relation("LeaveDeclarer", SetNull)`, `approvedBy User? @relation("LeaveApprover", SetNull)`
  - index `(employeeId, dateStart, dateEnd)` + `(status)`, `@@map("leave_declarations")`
- Ajouter relations inverses sur `User` : `declaredLeaves`, `approvedLeaves`.
- Ajouter relation sur `Employee` : `leaveDeclarations`.

### 1.2 Migration `apps/api/prisma/migrations/20260730120000_add_leave_declarations/migration.sql`
- `ALTER TYPE "attendance_summary_status" ADD VALUE IF NOT EXISTS 'LEAVE';`
- `ALTER TYPE "notification_type" ADD VALUE IF NOT EXISTS 'LEAVE_DECLARED';`
- `CREATE TABLE "leave_declarations"` (UUID PK, employee_id, date_start, date_end, note, declared_by, status default 'PENDING_APPROVAL', approved_by, timestamps) + index + FK vers employees (CASCADE) et users (SET NULL ×2). Mêmes motifs SQL que la migration work-accidents/overtime.

### 1.3 `apps/api/src/attendance/dto/manual-declarations.dto.ts`
- Ajouter `CreateLeaveDeclarationDto` (employeeId, dateStart, dateEnd, note?) — identique à `CreateSickLeaveDeclarationDto`.

### 1.4 `apps/api/src/attendance/manual-declarations.service.ts`
- `createLeave(dto, actor)` : guard `ensureLeaveDeclarer`, validation dateEnd≥dateStart, `ensureEmployeeVisible`, décision auto-approve via `leaveApprovalFor(actor)` (Admin/DRH/GRH → APPROVED sinon PENDING), create avec approvedById/approvedAt conditionnels, audit `leave.create`, notification (PENDING → `PENDING_APPROVAL` aux Admin/DRH ; APPROVED → `LEAVE_DECLARED`).

- `pendingApprovals()` retourne `{ overtime, compensations, leaves }`.
- Nouveaux helpers `ensureLeaveDeclarer`, `leaveApprovalFor`.

## Notes / risques
- La migration utilise `ALTER TYPE ... ADD VALUE` (déjà utilisé par la migration work-accidents, donc compatible avec la méthode Prisma en place). Le client Prisma doit être régénéré avant compilation.
- Refactor des privées `approve`/`reject` : interne, signatures publiques inchangées (overtime/compensation non impactés).
- Recoloration de SICK (rose→violet) et ACCIDENT (rouge→rouge foncé) : alignée sur le spec « badge distinct par statut ».
- Portée du fallback : l'overlay synthèse est appliqué uniquement au calendrier mensuel par employé (`employeeMonthlyCalendar`), pas à la liste multi-employés `listDaily` (pour rester ciblé et éviter un coût perf) — la liste quotidienne affiche déjà ses propres badges punch.
